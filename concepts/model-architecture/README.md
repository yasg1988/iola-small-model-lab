# Блок 1. Архитектура модели и sparse-подходы

Эти концепции вдохновлены MoE, условной памятью и ранним выходом из исследований 2026 года. Внутри обычного CLI мы не можем переписать слои установленной модели, поэтому тестируем практические аналоги на уровне рантайма.

## `conditional-memory`

Аналог DeepSeek Engram для нашего домена: факты не вспоминаются моделью, а достаются из MCP/API/локального индекса как внешняя память.

Пайплайн:

```text
вопрос -> разбор намерения/номера/сущности -> поиск в MCP/API -> структурированные факты -> ответ
```

Гипотеза: для городских данных это даст максимальную точность на фактах и минимальные галлюцинации.

## `sparse-escalation`

Аналог MoE по смыслу: активируем не всю "систему интеллекта", а минимально нужный уровень.

Пайплайн:

```text
простой факт -> прямой скилл
неоднозначный факт -> проверяющий
анализ -> большая локальная MoE-модель / Codex / API
```

Гипотеза: маленькая модель не должна получать задачи, которые требуют большой модели.

## `early-exit`

Если confidence поиска высокое, отвечаем сразу. Если confidence низкое, не даем слабой модели гадать.

Пайплайн:

```text
факты MCP + уверенность >= порог -> ответ
иначе -> запросить уточнение / отправить на проверку
```

Гипотеза: ранняя остановка снижает ошибки и задержку.
