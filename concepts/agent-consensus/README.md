# Блок 2. Консенсус агентов

Эти концепции проверяют не "толпу болтающих моделей", а строгий консилиум с ролями и ограничениями.

## `strict-skill`

Один скилл получает факты и отвечает шаблоном. Модель не участвует.

## `verify`

Один ответчик формирует ответ из фактов, второй проверяющий проверяет:

- ответ содержит только значения из фактов;
- сущность выбрана правильно;
- нет ложных предпосылок.

## `council`

Три роли:

- `router` - определяет слой и намерение;
- `retriever` - получает факты из MCP/API;
- `critic` - проверяет ответ и ловушки.

Гипотеза: консилиум нужен только на неоднозначных вопросах и вопросах с ловушками.
