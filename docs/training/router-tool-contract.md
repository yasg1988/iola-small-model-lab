# Контракт router-модели

Дата фиксации: 2026-05-27.

Этот контракт описывает выход маленькой модели-роутера. Модель не должна свободно отвечать по изменяемым городским данным. Ее задача - выбрать действие, инструмент и аргументы в строгом JSON.

## Базовый формат

```json
{
  "action": "tool_call",
  "tool": "get_entity_field",
  "args": {
    "layer": "schools",
    "inn": "1215067303",
    "field": "head"
  }
}
```

Выход модели должен быть одним JSON-объектом без markdown, пояснений и дополнительного текста.

## Разрешенные actions

| Action | Когда использовать |
| --- | --- |
| `tool_call` | Нужно вызвать API/MCP/RAG-инструмент. |
| `clarify` | Запрос неоднозначный, не хватает номера, названия, даты или слоя. |
| `refuse` | Пользователь просит непубличные, неподтвержденные или недоступные данные. |
| `direct_answer` | Только для стабильных исторических фактов, где источник не запрошен явно. |

## Разрешенные tools

| Tool | Назначение |
| --- | --- |
| `get_entity_field` | Точное поле учреждения по `layer + inn + field`. |
| `search_entities` | Поиск учреждений по названию, адресу или нестрогой формулировке. |
| `rag_search` | Поиск по историческим справкам, документам и текстовым источникам. |
| `get_current_official` | Текущая должность или персона по структурированному слою персоналий. |
| `get_official_by_date` | Должность или персона на дату/период. |

## Разрешенные layers

```text
schools
kindergartens
city_history
officials
documents
```

## Разрешенные fields для учреждений

```text
name
inn
address
email
website
phone
head
license_status
```

## Правила безопасности

1. Для школ и детских садов финальный факт всегда должен идти через `get_entity_field` или `search_entities`, даже если модель знает ИНН.
2. Для текущих должностных лиц и биографий использовать `get_current_official`, `get_official_by_date` или `rag_search`.
3. Если пользователь просит официальный источник, использовать `rag_search`, даже для стабильных исторических фактов.
4. Если объект или поле не распознаны уверенно, использовать `clarify`.
5. Если поле не является публичным или не входит в разрешенный список, использовать `refuse`.
6. Валидатор обязан отклонять любые actions, tools, layers и fields вне списков выше.

## Примеры

```json
{
  "action": "tool_call",
  "tool": "get_entity_field",
  "args": {
    "layer": "kindergartens",
    "inn": "1215066797",
    "field": "email"
  }
}
```

```json
{
  "action": "clarify",
  "question": "Уточните номер или название школы."
}
```

```json
{
  "action": "refuse",
  "reason": "field_not_public",
  "message": "В публичном наборе нет данных для ответа на этот вопрос."
}
```

```json
{
  "action": "direct_answer",
  "answer": "Йошкар-Ола основана в 1584 году. Современное название переводится как \"Красный город\"."
}
```
