# early-exit

## Что это

`early-exit` - стратегия раннего выхода. Если система уверена в найденном факте, она отвечает сразу.

## На какие исследования опираемся

- Идея условного вычисления и раннего выхода близка к sparse/MoE-подходам: [Mixtral of Experts](https://arxiv.org/abs/2401.04088)
- Для практики retrieval-first систем важен RAG: [Retrieval-Augmented Generation](https://arxiv.org/abs/2005.11401)

## Почему взяли

CLI должен быть быстрым. Если вопрос "какой телефон школы №2", нет смысла запускать сложный консилиум.

## Гипотеза

Ранний выход ускорит простые запросы без потери точности, если уверенность поиска высокая.

## Что проверяем

- Насколько безопасен быстрый ответ.
- Где проходит граница между обычным вопросом и ловушкой.
- Нужен ли отдельный детектор ложной предпосылки.

## Результат

| Датасет | Верно | Вывод |
| --- | ---: | --- |
| `simple-facts` | 100/100 | отлично для простых вопросов |
| `adversarial-facts` | 0/100 | нельзя применять без детектора ловушек |

## Решение

Оставить как внутреннюю оптимизацию, но не использовать на вопросах, где пользователь уже утверждает значение.
